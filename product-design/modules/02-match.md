# 模块 02 — 协作匹配（Match）

> 版本：v0.1 | 日期：2026-08-02

---

## 1. 模块概述

协作匹配模块帮助开发者找到合适的项目队友。不同于 LinkedIn 的简历导向，DevCave 的匹配基于真实的技术栈标签和 GitHub 贡献数据，用算法推荐互补的合作者，目标是让"找队友"像刷 Feed 一样自然。

**核心价值**：技术互补 > 技能重叠，找到真正能一起做事的人。

---

## 2. 用户故事

| ID | 角色 | 需求 | 验收标准 |
|----|------|------|---------|
| M-01 | 前端工程师 | 我想找一个 Rust 后端帮我做 SaaS | 推荐列表出现后端工程师，匹配度显示 |
| M-02 | 开发者 | 我想展示我的 GitHub 贡献图 | GitHub 数据正确渲染，含语言分布 |
| M-03 | 开发者 | 我想发一个"寻找协作者"帖子 | 帖子出现在分享 Feed，标记"寻人"类型 |
| M-04 | 开发者 | 我想给某人发协作请求 | 对方收到通知，可接受/拒绝 |
| M-05 | 开发者 | 我想查看我发出/收到的所有协作请求 | 请求列表，含状态（待处理/接受/拒绝）|
| M-06 | 开发者 | 我不想被陌生人打扰 | 可在设置中关闭协作请求接收 |

## 4. 核心交互流程

### 4.1 发起协作请求流程

```
[用户在推荐列表或档案页点击"发起协作"]
  ↓
[弹出协作请求 Modal]
  ↓
[填写项目简介（必填）+ 其他信息（可选）]
  ↓
[点击"发送请求"] → [校验：简介不为空，字数 > 20]
  ↓
  ├── 通过 → [发送成功 Toast: "请求已发送，等待 @username 回复"]
  │         → [Modal 关闭，该用户卡片显示"已发送请求"状态]
  └── 失败 → [inline 错误提示]
```

### 4.2 接受/拒绝请求流程

```
[收到新协作请求 → 站内通知🔔]
  ↓
[进入"我的请求"页，点击"查看 TA 的档案"]（可选步骤）
  ↓
  ├── [点击"接受合作"] → [弹出确认] → ["已成功匹配！现在可以通过站外联系方式交流"]
  │                                   → [双方各收到对方联系方式（如 GitHub 主页链接）]
  └── [点击"拒绝"] → [弹出可选理由选择（不做项目了/技术栈不合适/其他）] → [静默通知对方]
```

### 4.3 匹配算法触发时机

```
[用户更新技术档案（技术栈/寻找方向）]
  ↓
[系统重新计算匹配分]（异步，用户无感知）
  ↓
[下次刷新匹配页时展示新的推荐列表]

匹配分计算：
  Jaccard(用户A技术栈, 用户B寻找技术栈) × 0.5
  + 用户A寻找技术栈 与 用户B技术栈的 Jaccard × 0.3
  + 项目类型偏好匹配 × 0.2

排除规则：
  - 已发送请求（无论状态）的用户不再出现
  - 对方关闭了"接收协作请求"的用户不展示
  - 最近 3 个月已匹配过的用户降权展示
```

## 5. 边界与约束

| 规则 | 说明 |
|------|------|
| 发送频率 | 每天最多发送 5 个协作请求（防 spam） |
| 请求有效期 | 30 天后自动过期，双方可见 |
| 技术栈标签 | 每人最多 10 个，从预设列表选择（防低质标签） |
| 匿名保护 | 在对方接受请求前，双方均不可见对方联系信息 |
| 黑名单 | 用户可屏蔽特定用户（不再互相推荐，不可发请求） |
| 推荐数量 | 每次最多展示 24 个推荐，刷新可换一批 |
| 档案可见性 | 默认公开；可设置"仅匹配推荐时可见" |

## 6. 错误状态

| 场景 | 提示 |
|------|------|
| 对方关闭协作请求接收 | Toast: "对方暂不接受协作请求" |
| 发送频率超限 | Toast: "今天已发送 5 个请求，明天再来吧" |
| 档案不完整（无技术栈）| 推荐页顶部 Banner: "完善你的技术栈，获得更精准的推荐" |
| GitHub API 数据拉取失败 | 贡献图区域显示占位符 + "暂时无法加载 GitHub 数据" |
