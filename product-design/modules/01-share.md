# 模块 01 — 技术分享（Share）

> 版本：v0.1 | 日期：2026-08-02

---

## 1. 模块概述

技术分享模块是 DevCave 的内容核心，让开发者以 Markdown 格式发布技术文章和代码片段，支持语法高亮和版本 Diff 对比。目标是成为比博客更轻量、比微信公众号更技术的内容发布渠道。

**核心价值**：随手分享代码技巧，沉淀技术洞见，与同行讨论实现细节。

---

## 2. 用户故事

| ID | 角色 | 需求 | 验收标准 |
|----|------|------|---------|
| S-01 | 开发者 | 我想发布一段带语法高亮的代码片段 | 代码块正确高亮，支持至少 30 种语言 |
| S-02 | 开发者 | 我想写一篇 Markdown 技术文章，实时预览 | 编辑区与预览区同步滚动，延迟 < 100ms |
| S-03 | 读者 | 我想浏览有质量的技术内容 Feed | Feed 流加载 < 1s，内容不重复 |
| S-04 | 开发者 | 我想对比两个版本的代码差异 | Diff 高亮准确，新增绿色/删除红色 |
| S-05 | 读者 | 我想对一篇文章发表技术评论 | 评论支持代码块和 Markdown |
| S-06 | 开发者 | 我想看到谁收藏了我的文章 | 收藏通知，展示收藏者列表 |

## 4. 核心交互流程

### 4.1 发布文章流程

```
[用户点击"写文章"]
  ↓
[进入编辑器，title focus]
  ↓
[实时 Markdown 预览，自动保存草稿（30s间隔）]
  ↓
[点击"发布设置"] → [设置标签、可见性]
  ↓
[点击"发布"] → [校验：标题不为空、正文 > 50 字]
  ↓
  ├── 通过 → [发布成功 Toast] → [跳转到文章详情页]
  └── 失败 → [错误提示（红色高亮对应字段）]
```

### 4.2 版本 Diff 流程

```
[编辑器中点击"比较模式"]
  ↓
[底部面板升起，左侧默认为当前草稿]
  ↓
[右侧下拉选择历史版本]（历史版本按时间降序列表）
  ↓
[Diff 实时计算，逐行对比高亮]
  ↓
[可选：回滚到历史版本（二次确认弹窗）]
```

### 4.3 代码块语言选择

```
[在 ``` 后输入语言名] 或 [点击工具栏"语言▼"下拉选择]
  ↓
[支持的语言列表（前 10 个常用：TypeScript/Python/Rust/Go/Java/C++/Shell/SQL/JSON/YAML）]
  ↓
[选择后代码块实时重新高亮]
```

## 5. 边界与约束

| 规则 | 说明 |
|------|------|
| 标题长度 | 5-100 字符（中英混合均可） |
| 正文长度 | 50-50,000 字符 |
| 代码行数 | 单个代码块最多 1000 行 |
| 图片上传 | 单张 ≤ 5MB，格式 PNG/JPG/GIF/WebP，单篇最多 20 张 |
| 标签数量 | 最多 5 个，每个标签 2-20 字符 |
| 历史版本 | 保留最近 20 个版本，超出后自动删除最旧版本 |
| 草稿 | 每用户最多保存 20 个草稿 |
| 编辑时效 | 发布后 24 小时内可自由修改；超过后修改需附变更说明 |
| 删除 | 发布后可删除，但已有评论和收藏记录保留（匿名化） |

## 6. 错误状态

| 场景 | 提示方式 | 文案 |
|------|---------|------|
| 标题为空发布 | 红色边框 + inline 提示 | "标题不能为空" |
| 内容过短 | inline 提示 | "内容太短了，多说一点吧（至少 50 字）" |
| 图片过大 | Toast 错误 | "图片大小超过 5MB，请压缩后重试" |
| 网络断开自动保存失败 | 顶部 warning banner | "网络不稳定，草稿暂时无法同步，已保存到本地" |
| 发布频率限制 | Toast 警告 | "发布太频繁了，请 60 秒后再试" |
